# PDF Math Translate for Obsidian

![Obsidian Desktop](https://img.shields.io/badge/Obsidian-Desktop-7C3AED?logo=obsidian&logoColor=white)
![Version](https://img.shields.io/badge/version-0.7.2-blue)
![License](https://img.shields.io/badge/license-AGPL--3.0--only-green)

**English** | [简体中文](README_zh.md)

Use [PDFMathTranslate](https://github.com/Byaidu/PDFMathTranslate) directly inside Obsidian Desktop to translate scientific papers stored in your Vault. The plugin can output a monolingual translated PDF, or both monolingual and bilingual PDFs. A Markdown translation report can also be generated optionally and is disabled by default.

> An Obsidian desktop plugin for scientific PDF translation, Claudian-powered selection Q&A, and PDF++-based annotations.

Current version: `0.7.2`

## Features

- Start translation from the currently opened PDF, the command palette, the left ribbon, or the PDF file context menu;
- Configure page range, source language, target language, translation service, and model for each task through dropdown controls;
- Select multiple PDFs from an expandable file-tree interface, or right-click a folder to translate PDFs sequentially in batch, with overall progress and per-file results;
- Supports context-menu integration with both Obsidian's native file explorer and Notebook Navigator;
- The batch selector automatically excludes monolingual and bilingual PDFs generated by the plugin and checks whether the source PDF already has translations; existing translations are marked, reported, and skipped;
- Local mode calls the `pdf2zh.translate()` Python API directly;
- HTTP mode uses the project's existing `/v1/translate`, status-query, download, and cancellation endpoints;
- Displays translation progress and supports cancellation. Clicking outside the window or pressing Esc minimizes it into a compact bottom-right progress window that remains live and can be expanded at any time while the task continues in the background;
- While translation is running, new tasks can still be added from the progress window, mini progress window, toolbar, commands, or context menus. Each task keeps its own settings and enters a sequential waiting queue; translation services are never invoked concurrently;
- Before each translation, choose either “monolingual output only” or “monolingual + bilingual output”; generated files are written to the same folder as the source PDF;
- Markdown translation reports can be enabled separately and are disabled by default on a fresh installation;
- Each translation task uses a millisecond-resolution timestamp in its filename, so previous results are never overwritten;
- Generated notes can embed the bilingual PDF and record the source file, translation direction, service, and core version;
- Optionally use a Markdown note from the Vault as the custom prompt for PDFMathTranslate;
- OpenAI and OpenAI-compatible proxy services can automatically detect available text models and expose them in a model dropdown before each translation;
- The settings page provides a connection test that does not perform an actual translation;
- Integrates with the PDF++ custom context menu so selected text can be translated directly using the currently configured PDFMathTranslate service;
- After selecting text in PDF++, you can enter a question and send “question + exact selection + source page number” into Claudian/Codex;
- Claudian handles model switching, multi-turn conversation, and agent tools, so this plugin no longer maintains a second chat backend;
- After an answer is completed, annotations can be imported quickly from the context menu, command palette, or the left-side highlight icon;
- Generate Markdown annotations with PDF++ exact-selection backlinks in one action, or save the translated text together as a bilingual annotation;
- AI annotations store the question, answer, actual model used, and exact-selection backlink;
- Annotation Markdown files are stored beside the original PDF. Each paper maintains one stable annotation note, and the PDF itself is never modified;
- Selected-text translations are displayed in the right sidebar. Large selections are automatically split into chunks and translated serially, with automatic backoff and retry on HTTP 429 rate limits;
- The right-side translation panel can switch between detected models or accept a custom model ID, then retranslate the current selection with the selected model;
- Clicking a PDF++ highlight opens the corresponding annotation directly. Right-clicking a highlight allows that annotation to be deleted; highlights still do not interfere with selecting text again;
- After full-document translation, the plugin automatically creates a mapping between the source and translated PDFs. Double-clicking a location in either document jumps to the corresponding page and relative region in the paired PDF and briefly shows a location marker.

This plugin supports **Obsidian Desktop only**, because local mode needs to launch Python and HTTP mode also requires access to the desktop filesystem to save PDFs.

## Requirements

| Component | Requirement |
| --- | --- |
| Obsidian | Desktop `1.5.0` or later |
| PDFMathTranslate | A separate local source checkout is required; current tested baseline is `1.9.11` |
| Python | Local API mode requires `3.11` or `3.12`; using this repository's `scripts/setup-python.ps1` to create a dedicated `.venv` is recommended |
| PDF++ | Optional; used for selected-text translation and exact-selection annotations |
| Notebook Navigator | Optional; extends context-menu entry points |

## Architecture

```text
Obsidian commands / file menus / PDF++ selection menus / task window
                           │
                           ▼
                Vault input, output, and note management
                           │
            ┌───────────────┼───────────────┐
            ▼               ▼               ▼
      Local Python API   PDFMathTranslate HTTP API   PDF++ exact-selection backlinks
 PDF/short-text translation/Claudian Q&A   Full-PDF translation   Fast Markdown annotations
            │               │
            └───────┬───────┘
                    ▼
 PDFMathTranslate: layout analysis, formula protection, text translation, PDF reconstruction
```

The plugin does not copy or modify PDFMathTranslate's translation algorithms. The Python bridge (`bridge/pdf2zh_bridge.py`) only converts Obsidian JSON requests into the public `translate()` parameters exposed by the upstream project, and converts progress and results back into JSON events.

The bridge code has been separated from `main.js` and is stored independently under the `bridge/` directory. The plugin locates the bridge script using the absolute `configFile` path configured in settings (`path.dirname(configFile) + "/bridge/pdf2zh_bridge.py"`). Therefore, when installing the plugin, make sure the `bridge/` directory is placed alongside the other plugin files.

## Installation

### Install from GitHub Releases

1. Download `pdf-math-translate-x.y.z.zip` from the project's Releases page;
2. Extract it and copy `main.js`, `manifest.json`, `styles.css`, and the `bridge/` directory into `<Vault>/.obsidian/plugins/pdf-math-translate/`;
3. In Obsidian, reload and enable **PDF Math Translate** under “Settings → Community plugins”.

The current version has not yet been published to the official Obsidian Community Plugins registry, so manual installation is required.

### Build from Source

Node.js and pnpm are required:

```powershell
pnpm install
pnpm run build
pnpm test
```

After a successful build, the files required by Obsidian are:

- `main.js`
- `manifest.json`
- `styles.css`
- `bridge/pdf2zh_bridge.py`

### Install Build Artifacts

You can manually copy the files above into:

```text
<Vault>/.obsidian/plugins/pdf-math-translate/
```

Or use the installation script included in this repository:

```powershell
.\scripts\install-plugin.ps1 -VaultPath "C:\path\to\your\Vault"
```

Then open “Settings → Community plugins” in Obsidian, refresh the plugin list, and enable **PDF Math Translate**.

It is recommended to validate development builds in a test Vault first instead of installing them directly into your only production Vault.

## Configuration

### Local Python API (Recommended)

This mode **requires two separate items**, and they are not the same directory:

1. **A Python 3.11 / 3.12 virtual environment** used by the plugin at runtime;
2. **A local PDFMathTranslate source directory** from which the bridge script imports `pdf2zh`.

The most common source of confusion is that **the virtual environment is created inside this plugin repository, while the source directory is a separate checkout of the PDFMathTranslate repository**. Both paths must be configured in the plugin settings.

First, prepare the PDFMathTranslate source tree, for example:

```text
D:\src\PDFMathTranslate
```

Then run the following command from the root directory of this plugin repository:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-python.ps1 `
  -ProjectPath "D:\src\PDFMathTranslate" `
  -Python "C:\Python312\python.exe"
```

If the script was downloaded from the Internet, run this once first:

```powershell
Unblock-File .\scripts\setup-python.ps1
```

The script performs the following actions:

- Verifies that the specified Python version is `3.11` or `3.12`;
- Creates or updates `.venv` in the **current plugin project directory**;
- Installs the provided **local PDFMathTranslate source tree** into that `.venv`;
- Additionally pins the currently validated versions `peewee 3.18.2` and `tencentcloud-sdk-python-tmt 3.1.121` to avoid known Windows compatibility issues.

After the script completes, configure the following paths:

- **Python executable**: `.venv\Scripts\python.exe` inside this plugin directory;
- **PDFMathTranslate source directory**: your own upstream source checkout, for example `D:\src\PDFMathTranslate`.

Configure Obsidian in this order:

1. Open “Settings → PDF Math Translate”;
2. Select “Local Python API” as the connection mode;
3. Set “Python executable” to the `.venv\Scripts\python.exe` produced by the script;
4. Set “PDFMathTranslate source directory” to your `D:\src\PDFMathTranslate`;
5. Click “Check connection”;
6. Only start translating PDFs after the connection test succeeds.

If “Check connection” fails, verify these three items first:

- The configured interpreter is **the `.venv` Python belonging to this plugin**, not the system Python;
- The configured path is the **root directory of the PDFMathTranslate repository**, and it contains `pdf2zh\__init__.py`;
- The `.venv` was actually created with `setup-python.ps1` using the same `-ProjectPath`.

Translation-service credentials continue to be managed by PDFMathTranslate. You can use its `~/.config/PDFMathTranslate/config.json`, a custom configuration file, or system environment variables. This plugin does not store API keys.

When the selected service is “OpenAI” or an “OpenAI-compatible API”, the plugin queries `/v1/models` at the configured endpoint when the translation window opens and adds returned text models to the dropdown list. Models can also be refreshed manually from the settings page or translation window. Automatic detection only reads the existing configuration and does not modify the configuration file. If a proxy does not implement the models endpoint, you can still manually enter the exact model ID.

### HTTP API (Optional)

HTTP mode is intended for users who already have a deployed PDFMathTranslate service. According to the upstream `docs/APIS.md`, the server requires Flask, a Celery worker, and Redis, for example:

```powershell
pip install "pdf2zh[backend]"
pdf2zh --flask
pdf2zh --celery worker
```

In the plugin settings, select “HTTP API”, enter the service address (default: `http://127.0.0.1:11008`), and run the connection check. The connection test only confirms that Flask is reachable; Redis and the Celery worker are validated when an actual translation task is submitted.

Note: the current upstream HTTP API does not provide file-path handling corresponding to the `compatible` parameter, so the plugin's “compatibility mode” only works with the Local Python API.

## Usage

Open a PDF stored in the Vault, then use any of the following entry points:

- Click the language icon in the left ribbon;
- Run “PDF Math Translate: Translate current PDF” from the command palette;
- Right-click a PDF in the file list and choose “Translate with PDF Math Translate”;
- When the current view is not a PDF, run “Select and translate PDF”;
- Run “Batch select and translate PDFs”, choose files or entire folders from the expandable Vault file tree, and process them sequentially with shared settings;
- Right-click a folder in the file list and choose “Batch translate PDFs in this folder”; the plugin first displays “pending / total”, then lists and skips files that already have translations before starting.

Page ranges use human-friendly 1-based numbering, for example `1-3,5`. Leave the field empty to translate the entire document.

### PDF++ Selected-Text Translation, Claudian Q&A, and Quick Annotations

1. Install and enable PDF++, and enable custom PDF context menus in the PDF++ settings;
2. Keep “Enable PDF++ integration” turned on under “Settings → PDF Math Translate”;
3. Select text in a PDF and right-click:
   - Choose “Translate selected text” to view the translation in the right sidebar, copy it, or save it as a bilingual annotation;
   - Choose “Send selected text to Claudian Q&A”, enter a question, and let the plugin populate Claudian without sending automatically;
   - In Claudian, confirm the provider, model, and question, then send it. You can continue the conversation with follow-up questions;
   - After the answer is complete, choose “Import Claudian's latest answer as annotation”, or use the command palette / left-side highlight icon;
   - Choose another model in the right sidebar and click “Retranslate with this model” to compare translations of the same selection across models;
   - Choose “Quick-annotate selected text” to immediately save the source text and an exact-location link into the annotation note;
   - Click an existing highlight to open the annotation note directly at the corresponding entry;
   - Right-click an existing highlight and choose “Open corresponding annotation” or “Delete this annotation”. After deletion, you can click “Undo deletion” in the notification within 15 seconds;
4. Annotation notes are stored in the same folder as the source PDF. If a folder contains one paper, the note is simply named `批注.md`; if multiple PDFs share the folder, a short paper identifier is added automatically, for example `DAC2026-900 - 批注.md`.

Selected-text translation still uses the Local Python API, while Q&A is handled by Claudian's Codex provider. The plugin records the active Claudian tab, conversation, and message count when the question is created, and only imports new assistant responses produced after that question, preventing answers from older conversations from being attached to the current selection. Translation selections longer than 2,500 characters are split at natural boundaries and translated serially. Q&A selections are limited to 50,000 characters.

Quick annotations use Obsidian's native `#page=…&selection=…` deep links; PDF++ renders those backlinks as selection highlights. The plugin matches annotations using the clicked location, the same PDF, page number, and exact selection. A normal click only opens the annotation; deletion must be explicitly chosen from the highlight context menu. The highlight layer still ignores drag events, so selecting text again does not accidentally open an annotation. If PDF++ cannot return the selection coordinates, the plugin clearly reports the issue and falls back to a page-level link. Page-level links do not create selection highlights and must be managed from the annotation note.

Default output structure (monolingual PDF only, without a Markdown translation report):

```text
Paper folder/
├─ paper.pdf
├─ 批注.md
└─ Paper Title - Monolingual Translation - 20260813-153012-123.pdf
```

When “monolingual + bilingual output” is selected, an additional bilingual PDF is generated. When “Generate Markdown translation report” is enabled, a `翻译说明 - timestamp.md` file is also added to the directory. The translation report is not a required output of PDFMathTranslate.

Monolingual translations, bilingual translations, and translation reports always use the original PDF title as the filename prefix, for example `Paper Title - Monolingual Translation - timestamp.pdf`. If the title is too long, it is safely truncated and given a checksum suffix. Annotation files continue to use the shorter naming scheme inside a single-paper folder.

Translation uses the system temporary directory while running. Output files are written to the source-paper directory only after successful completion, and temporary files are cleaned up automatically. Files already written into the Vault are never overwritten by later tasks.

After translation starts, you can click “Add task” in either the full progress window or the compact bottom-right progress window. New tasks can also be added from the left-side batch translation icon, the command palette, or file context menus. New batches display “Added to translation queue” and start automatically after the current file finishes. Running “Cancel current PDF translation and waiting queue” terminates the current file and removes all tasks that have not yet started.

Source/translation mappings are stored in plugin data. Newly generated monolingual and bilingual translations are paired precisely with their source PDFs. Older translations generated by this plugin before an upgrade can also be detected from their filenames as long as they remain in the same directory and still follow the timestamp naming convention. Double-click navigation uses the same page number plus relative position within the page, which works well with PDFMathTranslate outputs that preserve page structure. If the translated PDF is substantially reflowed, this is not semantic paragraph alignment.

## API Selection Notes

PDFMathTranslate's upstream English `README.md` and `docs/APIS.md` document both the Python and HTTP APIs, and the code exports `translate` and `translate_stream` from `pdf2zh.__init__`. At the same time, `docs/README_zh-CN.md` previously contained wording stating that the “API is temporarily deprecated”, so the upstream documentation is not entirely consistent.

This plugin uses the following compatibility strategy:

- Local integration primarily relies on the public Python API that actually exists in the upstream implementation;
- HTTP integration strictly uses endpoints that are already implemented upstream;
- All calls are isolated behind adapters and a small bridge layer;
- If the upstream API changes in the future, only the adapter needs to be replaced; Vault files and interaction logic remain unaffected.

## Privacy and External Access

- Local Python mode reads the selected Vault PDF and allows PDFMathTranslate to access the network through the chosen translation service;
- Claudian Q&A sends the question, selected text, PDF path, and page number to its Codex provider only after you confirm submission; data-retention behavior depends on the configured proxy/provider;
- HTTP mode uploads the selected PDF to the server you configured;
- If a custom prompt note is configured, the entire note is sent to the selected translation service together with the translation request;
- The plugin includes no telemetry, advertising, or additional account system;
- The plugin does not write API keys into `data.json`.

# TypeScript type checking and production build

## Known Limitations

- Obsidian Desktop only;
- Selected-text translation only supports the Local Python API;
- The Claudian bridge depends on `appendToActiveInput()` and active-tab message state currently exposed by `realclaudian`; integration should be retested after upgrading Claudian;
- Q&A currently uses the user's selected text as its primary context and does not automatically retrieve the full PDF. When full-document context is needed, continue using agent tools in Claudian;
- If PDF++ cannot return selection coordinates, annotations fall back to page-level links and do not produce exact-selection highlights;
- Double-click synchronization between source and translated PDFs navigates by page number and relative position within the page rather than sentence-level semantic alignment. If the source or translated PDF is manually renamed or moved, the old mapping may require retranslation or restoration of the original file location;
- PDFMathTranslate configuration formats and APIs may change in future upstream versions. Validate upgrades in a test Vault before using them in production.
